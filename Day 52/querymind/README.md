# QueryMind

AI-powered SQL query generator for data analysts. Paste a database schema, ask a question in plain English, get back a correct SQL query with a plain-English explanation.

**Live demo:** https://querymind-3msv.onrender.com

Built as a 10-day capstone project for the **AB Talks 60-Day Claude AI Challenge**.

---

## The problem

Data analysts spend a significant part of their day translating business questions into correct SQL syntax, especially when working with unfamiliar schemas. It's repetitive, easy to get wrong, and slows down the actual analysis work.

## The solution

A focused, single-purpose tool:
1. Paste your database schema as `CREATE TABLE` statements.
2. Ask your question in plain English.
3. Get back a correct, ready-to-use SQL query and a plain-English explanation of what it does.

No login required. No query execution (nothing ever runs against a real database — the app only generates SQL text). No chat, no file uploads. One clear job, done well.

## Features

- Schema-aware SQL generation grounded only in the tables/columns you provide
- Plain-English explanation alongside every generated query
- Built-in validation warning if the AI ever references a table not present in your schema
- Copy-to-clipboard for the generated SQL
- Clean, responsive, accessible interface with smooth micro-interactions
- Rate-limited and hardened for public use (no login required, but abuse-resistant)

## Running locally

**Prerequisites:** Python 3.11+, a free Groq API key (get one at [console.groq.com](https://console.groq.com), no card required).

```bash
# 1. Navigate to the project folder
cd Day 52/querymind

# 2. Create and activate a virtual environment
python -m venv venv
# Windows (Git Bash):
source venv/Scripts/activate
# Windows (PowerShell):
venv\Scripts\Activate.ps1

# 3. Install dependencies
pip install -r requirements.txt

# 4. Set up your API key
cp .env.example .env
# then edit .env and paste your GROQ_API_KEY

# 5. Run the app
uvicorn app.main:app --reload --port 8000
```

Open `http://127.0.0.1:8000` in your browser.

## API

Three endpoints, all documented in detail in `../API.md`:

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | Serves the frontend |
| `POST` | `/api/generate` | Generates SQL + explanation from a schema and question |
| `GET` | `/api/health` | Health check |

Interactive API docs (auto-generated by FastAPI) are available at `/docs` when running locally.

## Security notes

- No authentication or user accounts (by design — see PRD)
- The generated SQL is **never executed** against any database — it's text output only, which also means there's nothing to inject into
- `/api/generate` is rate-limited (15 requests/minute per IP) to protect the AI service quota
- Basic security headers are set on every response (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`)
- The API key lives only in environment variables (`.env` locally, Render's dashboard in production) — never committed to the repository

## What's out of scope (by design)

DAX/Power BI generation, live query execution, multi-turn conversation, schema file uploads, and user accounts were all deliberately excluded to ship a focused, reliable v1.0 within a 10-day solo build. See `../PRD.md`-equivalent docs in `Day 51/` for the full reasoning.
